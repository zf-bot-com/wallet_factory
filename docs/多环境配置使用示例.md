# 多环境配置使用示例

## 场景 1：本地开发

在本地开发时，使用开发环境配置（连接本地 Redis）：

```bash
# 编译开发版本
make linux

# 或者显式指定
make linux ENV=dev

# 输出：
# 准备配置文件: config.env.dev -> config.env
# ✅ 配置文件已准备: dev 环境
# 编译 Linux 版本 (环境: dev)...
# ✅ 编译完成: factory-linux (dev)
```

## 场景 2：部署到生产环境

部署到生产服务器时，使用生产环境配置：

```bash
# 部署生产环境
./deploy.sh prod

# 或者指定服务器
./deploy.sh prod gpu /srv

# 输出：
# ==========================================
# 开始部署 trap-factory 到服务器 gpu
# 环境: prod
# ==========================================
#
# [1/5] 编译 Linux 版本 (环境: prod)...
# 准备配置文件: config.env.prod -> config.env
# ✅ 配置文件已准备: prod 环境
# ...
```

## 场景 3：添加测试环境

如果需要添加测试环境：

```bash
# 1. 创建测试环境配置文件
cp config.env.example config.env.test

# 2. 编辑配置文件
vim config.env.test

# 3. 编译测试版本
make linux ENV=test

# 4. 部署测试版本
./deploy.sh test test-server /srv
```

## 场景 4：验证配置

在编译前验证配置是否正确：

```bash
# 准备配置
make prepare-config ENV=prod

# 查看配置内容
cat config.env

# 清理配置
make clean-config
```

## 场景 5：错误处理

如果指定的环境不存在：

```bash
$ make linux ENV=staging

# 输出：
# 准备配置文件: config.env.staging -> config.env
# 错误: 配置文件 config.env.staging 不存在
# 可用的配置文件:
# config.env.dev
# config.env.example
# config.env.prod
# make: *** [prepare-config] Error 1
```

## 场景 6：多平台编译

为不同平台编译不同环境的版本：

```bash
# Linux 生产版本
make linux ENV=prod

# Windows 开发版本
make win ENV=dev

# macOS 生产版本
make mac ENV=prod
```

## 配置文件对比

### config.env.dev（开发环境）
```env
REDIS_ADDR=127.0.0.1:6379
REDIS_PASSWORD=
REDIS_DB=0
```

### config.env.prod（生产环境）
```env
REDIS_ADDR=216.126.224.148:6379
REDIS_PASSWORD=VHK3dtw*zpx0pdb_kxp
REDIS_DB=0
```

## 最佳实践

1. **本地开发**：始终使用 `dev` 环境
2. **生产部署**：明确指定 `ENV=prod`
3. **配置安全**：不要将 `config.env.prod` 提交到版本控制
4. **验证配置**：部署前先用 `prepare-config` 验证配置文件
