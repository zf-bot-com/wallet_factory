# 批量部署到多个服务器

## 概述

deploy.sh 脚本支持一次编译，批量部署到多个服务器。这对于管理多个 worker 节点非常有用。

## 服务器配置文件

### 配置文件格式

服务器列表保存在 `servers.env.[环境]` 文件中，格式如下：

```bash
# 格式 1：只指定服务器地址（使用默认路径 /srv）
gpu
worker-01
worker-02

# 格式 2：指定服务器地址和路径
gpu:/srv
worker-01:/home/user/trap-factory
worker-02:/srv

# 注释行（以 # 开头）和空行会被忽略
```

### 配置文件列表

- `servers.env.dev` - 开发环境服务器列表
- `servers.env.prod` - 生产环境服务器列表
- `servers.env.example` - 配置示例

## 使用方法

### 1. 配置服务器列表

编辑对应环境的服务器配置文件：

```bash
# 编辑生产环境服务器列表
vim servers.env.prod
```

示例配置：

```bash
# 生产环境服务器列表
gpu:/srv
worker-01:/srv
worker-02:/srv
worker-03:/srv
```

### 2. 执行批量部署

```bash
# 部署到生产环境的所有服务器
./deploy.sh prod

# 部署到开发环境的所有服务器
./deploy.sh dev
```

## 部署流程

脚本会按以下步骤执行：

1. **编译**：编译一次 Linux 版本（使用指定环境的配置）
2. **打包**：打包一次程序文件
3. **环境检查**：检查所有服务器的 GPU 环境
   - 检查 clinfo 是否安装
   - 检查是否能检测到 GPU 设备
   - 如果有服务器环境异常，提供自动修复选项
4. **上传**：批量上传到所有服务器（跳过环境异常的服务器）
5. **部署**：在每个服务器上解压和安装

## 错误处理

### 环境检查失败

如果某些服务器的 GPU 环境未配置，脚本会：

1. 显示环境异常的服务器列表
2. 提供修复方法
3. 询问是否自动修复
4. 如果选择自动修复，会在所有异常服务器上执行安装命令
5. 重新检查环境
6. 如果仍有异常，提示手动修复

示例：

```bash

==========================================

```

### 上传失败

如果某些服务器上传失败，脚本会：

1. 显示失败的服务器列表
2. 询问是否继续部署到成功上传的服务器
3. 跳过失败的服务器，继续部署其他服务器

示例：

```bash
[ERROR] 上传失败: worker-03
[INFO] 上传统计: 成功 2, 失败 1
[WARNING] 以下服务器上传失败:
  - worker-03

是否继续部署到成功上传的服务器? (y/n)
```

### 部署失败

如果某些服务器部署失败，脚本会：

1. 继续部署其他服务器
2. 在最后显示部署统计
3. 提示检查失败的服务器

## 优势

1. **效率高**：只编译一次，批量上传和部署
2. **可靠性**：自动处理错误，不会因为一个服务器失败而中断整个流程
3. **可视化**：清晰的进度显示和统计信息
4. **灵活性**：支持不同路径的服务器配置

## 注意事项

1. **SSH 配置**：确保已配置 SSH 免密登录到所有服务器
2. **权限**：确保有权限在目标路径创建和修改文件
3. **备份**：脚本会自动备份旧版本，但建议定期清理备份文件
4. **配置安全**：`servers.env.prod` 包含服务器信息，已加入 `.gitignore`

## 批量管理服务

部署完成后，可以使用以下脚本批量管理服务：

```bash
# 批量查看服务状态
for server in gpu worker-01 worker-02; do
    echo "=== $server ==="
    ssh $server 'sudo supervisorctl status trap-factory'
done

# 批量重启服务
for server in gpu worker-01 worker-02; do
    echo "=== 重启 $server ==="
    ssh $server 'sudo supervisorctl restart trap-factory'
done

# 批量查看日志
for server in gpu worker-01 worker-02; do
    echo "=== $server 日志 ==="
    ssh $server 'sudo supervisorctl tail trap-factory' | head -20
done
```

## 添加新服务器

添加新服务器非常简单：

1. 在 `servers.env.prod` 中添加新服务器地址
2. 运行 `./deploy.sh prod`
3. 脚本会自动部署到所有服务器（包括新添加的）

示例：

```bash
# 编辑配置文件
vim servers.env.prod

# 添加新服务器
# worker-04:/srv

# 重新部署
./deploy.sh prod
```
